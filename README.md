# LockSentry AI 🛡️

**AI-Assisted Software Dependency Security Gate**  
*Enforcing Deterministic Security Policies Backed by Verified OSV.dev Intelligence and Local Open-Weight AI (Gemma 2 2B)*

---

## 📌 Overview

**LockSentry AI** is a pre-merge dependency security gate that inspects software manifests and lockfiles before third-party changes enter a production codebase.

Modern software projects constantly face supply-chain attacks, unpatched vulnerabilities, accidental package downgrades, and ambiguous unpinned dependencies. LockSentry AI solves this problem by combining:

1. **Deterministic Security Policies** with absolute veto authority (`PASS`, `BLOCK`, `REVIEW`).
2. **Official OSV.dev Intelligence** directly queried from Google's Open Source Vulnerability database.
3. **Local Open-Weight AI (Google Gemma 2 2B)** running on your own machine to analyze vulnerability contexts, evaluate upgrade trade-offs, identify uncertainty gaps, and generate actionable maintainer guidance.

> [!IMPORTANT]
> **Deterministic Precedence Guarantee**: LockSentry AI strictly enforces deterministic security rules. The AI model operates purely as an evidence-grounded reasoning and explanatory layer—**the model NEVER overrides a security block decision**, and a failed model inference never skips a security check.

---

## 🚀 Key Features

- **Multi-Ecosystem Support**: Parses Python `requirements.txt` (exact pins, specifier ranges, inline comments, markers, VCS URLs) and npm `package-lock.json` (v1, v2, and v3 schemas).
- **Comparative Differential Gate**: Compares existing vs proposed manifests to identify `ADDED`, `UPDATED`, `DOWNGRADED`, and `REMOVED` packages.
- **Downgrade Attack Detection**: Automatically detects and blocks version rollbacks that might re-introduce previously patched vulnerabilities.
- **Verified Vulnerability Intelligence**: Retrieves live CVE aliases, GHSA IDs, CVSS scores, affected ranges, and documented fixed versions via the official Google OSV API.
- **Local Open-Weight Model Inference**: Powered by local **Google Gemma 2 2B** (`gemma2:2b`) running via Ollama. No proprietary manifests or private package names are ever leaked to third-party hosted cloud APIs.
- **Automated Evidence Grounding Verification**: Verifies every claim, package, and CVE generated by the AI against input OSV data, detecting and flagging any hallucinated references.
- **Zero Code Execution**: Performs static token parsing and API evidence lookups. Never executes `setup.py`, `npm install`, or untrusted repository scripts.
- **Streamlit Web Dashboard**: Interactive UI with status badges, KPI metrics, deep-dive trade-off cards, and preset security scenario loaders.
- **Exportable Audit Artifacts**: One-click export of structured JSON audits (`locksentry_report.json`) and GitHub-flavored Markdown reports (`locksentry_report.md`).

## 🤖 Open-Weight AI Verification

LockSentry AI strictly complies with open-weight AI requirements:

- **Configured Model**: `gemma2:2b` (Google Gemma 2, 2.6B parameters, Q4_0 quantization).
- **Model License**: [Gemma Terms of Use](https://ai.google.dev/gemma/terms) (Open-weight, permitted for commercial and research use).
- **Local Inference Runtime**: [Ollama](https://ollama.com/) running locally on `http://localhost:11434`.
- **Secondary Fallback Model**: `llama3:latest` (Meta Llama 3 8B Instruct, Meta Llama 3 Community License).
- **Hardware Footprint**: Operates smoothly on consumer hardware with 4GB VRAM (e.g. NVIDIA GTX 1650) or CPU-only mode.
- **Investigation of "Gemma 4"**: We verified that Google's released open-weight models include Gemma 1, Gemma 2 (2B, 9B, 27B), and Gemma 3 preview. "Gemma 4" does not exist in open-weight model registries. Gemma 2 2B was selected as the verified, lightweight model providing fast local inference and high schema adherence.
- **Meaningful Work Performed**: Rather than merely summarizing text, Gemma 2 2B analyzes the contextual exposure of vulnerabilities, evaluates migration trade-offs (breaking change risk vs CVE elimination), flags supply-chain ambiguities, and drafts targeted maintainer review checklists.

## 🛠️ Installation & Setup

### Prerequisites
- Python 3.10 or 3.11
- [Ollama](https://ollama.com/) installed and running locally
- Git

### 1. Clone Repository & Install Python Dependencies
```bash
git clone https://github.com/your-org/LockSentry-AI.git
cd LockSentry-AI
pip install -r requirements.txt
```

### 2. Pull the Open-Weight AI Model
Ensure Ollama is running, then pull the Google Gemma 2 2B model:
```bash
ollama pull gemma2:2b
```
*(Optional: If you wish to use Llama 3 as a fallback, run `ollama pull llama3:latest`)*.

---

## 💻 Running LockSentry AI

### 1. Launch the Streamlit Dashboard
```bash
streamlit run app.py
```
Open your browser to `http://localhost:8501`.

### 2. Run the Automated Test Suite (28 Tests)
```bash
python -m pytest -v
```
*(Runs unit tests, mock error simulations, live OSV lookups, and local Gemma 2 2B inference tests).*

### 3. Run the Empirical Benchmark
```bash
python -m benchmark.run_evaluation
```
*(Executes baseline vs AI comparative evaluation and outputs empirical performance metrics).*

## 📜 Deterministic Security Policy Rules

LockSentry AI enforces 3 deterministic outcomes:

| Outcome | Trigger Condition | Developer Action Required |
|---|---|---|
| **🔴 BLOCK** | Confirmed vulnerability (CRITICAL / HIGH / CVSS >= 7.0), any confirmed vulnerable proposed package, or unauthorized version downgrade. | **Reject PR / Build**. Upgrade dependency to the recommended fixed version. |
| **🟡 REVIEW** | Unpinned floating version constraint (`>=`, `~=`), major breaking SemVer bump (e.g. `1.x` -> `2.x`), or OSV intelligence retrieval failure. | **Human Review Required**. Pin exact version in lockfile and verify API backward compatibility. |
| **🟢 PASS** | All packages pinned with zero known advisories in the OSV database. | **Approve Change**. Dependency meets current deterministic baseline. |

---

## 🛡️ Responsible Disclosure & Limitations

1. **Intelligence Scope**: OSV vulnerability intelligence reflects publicly disclosed security advisories. Absence of an advisory does NOT guarantee zero vulnerabilities.
2. **Deterministic Authority**: Open-weight AI models serve an advisory and explanatory role; they possess zero authority to override deterministic policy rejections.
3. **Execution Safety**: LockSentry AI operates purely via static manifest inspection and API evidence. No untrusted package install scripts were executed.
